Для тестування використовувався списковий endpoint:

`api.php?resource=workouts`

## 1. Початковий стан

У початковій реалізації використовувалась проблема N+1.

Спочатку виконувався один SQL-запит для отримання списку тренувань, після чого для кожного тренування окремо виконувався запит для обчислення сумарних калорій тренувань такого самого типу.

Для 8 тренувань виконувалось:

- 1 запит для списку;
- 8 додаткових запитів у циклі;
- разом 9 SQL-запитів.

### Профілювання до оптимізації

При повторних запусках час виконання становив приблизно 4–6 мс після першого холодного запуску.

Пікове використання пам'яті:

`2 MB`

Кількість SQL-запитів:

`9`
