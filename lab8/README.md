## Міграція

`security_migration.sql` додає `owner_id` та індекс
`idx_workouts_owner`.

Файл потрібно виконати один раз, якщо колонка та індекс ще не були створені.

Для демонстрації захисту тестовий запис `id=15`
отримує `owner_id=2`, тоді як навчальний поточний користувач має `user_id=1`.

## Реалізований захист

### SQL Injection

Фільтр `type` використовує `prepare()` / `execute()`.

Payload:

```text
' OR '1'='1
```

не змінює SQL-запит.

### XSS

Поле `type` виводиться на фронтенді через `textContent`.

Payload:

```html
<script>alert(1)</script>
```

відображається як текст і не виконується.

### CSRF

CSRF-токен зберігається в PHP-сесії, передається у POST-запиті
та перевіряється через `hash_equals()`.

Запит без токена або з неправильним токеном повертає:

```text
403 Forbidden
```

### Серверна валідація

PHP перевіряє обов'язкові поля, додатну тривалість,
невід'ємні калорії та формат дати.

### Захист дій

Доменні дії через GET блокуються кодом:

```text
405 Method Not Allowed
```

Редагування перевіряє `owner_id`. Чужий запис змінити не можна.

### Помилки

Технічні подробиці записуються через `error_log()`.
Користувач отримує загальне повідомлення без `PDOException` або `SQLSTATE`.
